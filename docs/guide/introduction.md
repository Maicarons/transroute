# 项目介绍

TransRoute（物流拓扑计算系统）是一个以**真实地理数据**为基础的物流网络建模与路径计算工具。它面向的真实场景是：一件货物从发货厂出发，依次经过物流站点、当地物流中心、城市节点、中转枢纽，通过干线跨区运输，再逐级下行到目的地城市、物流中心、物流站点，最终配送到终点。

## 它解决什么问题

传统物流规划或教学 demo 常常出现两类问题：

1. **坐标/里程是编的**——地图上城市位置随手放，两点距离用直线硬算，结论不可信。
2. **拓扑过于扁平**——只有「城市 A → 城市 B」一条边，忽略了真实物流「多级分拨、逐级汇聚」的轴辐式结构。

TransRoute 从设计上规避这两点：

- **真实坐标**：节点来自真实城市目录（`src/data/cities.ts` 的 `REAL_CITIES`）、OSM Nominatim 或高德地理编码；路径来自 OSRM / 高德真实路网。
- **真实拓扑**：四级轴辐式层级（站点 / 当地物流中心 / 城市节点 / 中转枢纽），自动组网遵循「低层级就近连高层级 + 枢纽间干线网格」。

## 核心设计原则

> **禁止任何模拟 / 虚构数据。** 这是项目的硬约束。所有进入系统的坐标、里程、耗时都必须来自真实数据源（城市目录、OSM、高德、OSRM）；当真实数据拉取失败时才允许用 haversine 直线距离作为**兜底估算**，并在结果中明确标记为「非真实（real=false）」，而非伪装成真实数据。

## 两大子项目

| 子项目 | 位置 | 说明 |
| --- | --- | --- |
| 物流拓扑系统（主应用） | 仓库根目录 `src/` | React + Vite + MapLibre + Zustand，提供节点/边编辑、自动组网、真实路网权重、多目标路径计算与可视化。 |
| 《物流大亨》（衍生游戏） | `game/` | 完全独立的 Vite + React + TS 工程，复用真实城市坐标与地图组件，是一个经营模拟小游戏。 |

两个子项目**互相独立**：游戏不 import 主应用源码，依赖完全自管（详见[项目结构](/reference/project-structure)）。

## 数据来源总览

| 用途 | 来源 | 坐标基准 | 是否需要 Key |
| --- | --- | --- | --- |
| 离线城市坐标 | `src/data/cities.ts`（`REAL_CITIES`，约 40 个中国城市） | WGS-84 | 否 |
| 浏览器实时地理编码 | OSM Nominatim / 高德 | WGS-84 / GCJ-02 | 高德需要 |
| 真实公路里程与耗时 | OSRM 公共服务器 / 本地 OSRM / 高德路径规划 | WGS-84（高德需纠偏） | 高德需要 |
| 底图 | MapLibre + Carto（OSM 数据） | WGS-84 | 否 |

> 关于底图与国界：Carto 基于 OSM，存在中国国界不合规、国内访问偏慢、无中文标注等问题。项目当前默认使用 Carto 底图（与 WGS-84 节点零偏移）。如需合规底图，可接入天地图（同为 WGS-84，需免费 `tk` Key），现有节点位置无需任何改动。
